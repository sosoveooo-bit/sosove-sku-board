# JP25 无法生图：策划正文为空

## 原因与证据

用户截图显示通用“远端节点正在切换账号”错误，同时显示旧套图 25/25、线上七层 Prompt 0/25。

本地代理使用记录表明，同一整套摄影策划请求多次返回 HTTP 成功，但 completion_tokens=6500 且 reasoning_tokens=6500。代理默认给 DeepSeek 开启 high thinking，全部输出额度用于推理，未留下方案正文。后端将空字符串当作调用成功，没有触发备用模型；方案解析失败后，前端没有保存具体错误，误显示通用生图节点报错。

## 修复

- 仅 JP25 DeepSeek 策划请求发送代理支持的 `thinking.type=disabled`，保留当前模型、模型链和原有输出额度；其他模型及其他模块不改此参数。
- 导演 HTTP 200 但正文为空仍视为失败；JP25 明确 length 截断的正文也不作为成功结果，使用现有备用模型机制。
- 保存和展示真实策划错误及上游原因，失败阶段不标记全部完成。
- 日本25图监控仅统计匹配当前方案版本、签名和逐图修订的图片；旧图片继续保留，恢复卡片说明历史数量与当前进度。
- 更新静态资源版本，避免浏览器复用旧错误处理脚本。

## 验证

- 新后端回归先复现空正文被误判成功及缺少输出保护，再验证空正文、空文本数组、截断 JSON、备用模型、JP25/其他模块参数隔离。
- 前端运行真实策划函数，覆盖接口异常、0/25 部分方案、真实原因保存、历史25图保留、当前版本计数与成功重试。
- 77 项模块检查：75 通过、2 项既有跳过；51 项套图和导演检查通过。工作台试样/续生成回归和已有错误展示回归通过。
- 使用当前 DeepSeek 服务实际验证：完整25页摄影方案约40.1秒返回，finish_reason=stop；再验证前3页七层提示词约21.8秒完整返回。
- 验证未提交真实生图请求。没有修改模型选择、代理全局设置或删除图片。浏览器自动化连接失败，界面逻辑通过离线执行真实前端函数验证。
