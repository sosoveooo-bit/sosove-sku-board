# 长图片规划截断与断点续接

## 根因
日本 30 页任务 `9085826c7f57446f8a5c2d983b2a3902` 的规划响应多次 finishReason=length。单次要求完整 30 页、输出上限 11000 tokens，导致 JSON 截断；格式重试仍请求整套，解析器又从残缺外层扫描到内部对象，误报缺少 pages。

## 方案
- 图片规划按最多 8 页请求，保留全局营销/视觉方向、已规划页摘要和未覆盖卖点；逐批保存，不固定各页版式。
- 引用修正和版式修正也分批保存；输出截断或反复格式失败时自动减小请求页数，最小 1 页，有限停止。
- 明确识别输出长度上限，不对相同大请求再做格式重试；禁止从截断外层 JSON 接受内部对象作为完整阶段。
- 保留产品缓存和已完成阶段；旧有效规划草稿兼容，续接只请求缺页。
- 离线覆盖 30 页、截断分批、时间切片、修正中途失败、错误页码及不伪造残缺 JSON；验证当前任务的实际规划链路，保留进度，不生成整套图片或增加后置审核。

## 验证结果
- 全量 Visual Agent 99 项通过；随后增加完整 JSON 封套兼容性用例，结构化与分批专项 21 项通过。导演传输/模型设置 21 项及前端参考图、错误显示、方案同步回归通过。
- 真实截图任务的 30 页规划完成：8 + 8 + 8 + 6 页分批创建，再单独修正第 5 页；5 次请求均 finishReason=stop。时间切片后继续复用已完成的 30 页草稿。
- 产品分析、营销策略、视觉导演结果均未重跑；任务 ID 不变。未请求动态 Prompt 或生成图片；没有新增生成后审核。
- 另一个正在使用的任务保持运行，未为验证强停；最终确认所有策划租约、图片任务空闲后重载 8793，健康检查正常。
- 旧失败返回只存有摘要/hash，完整截断正文未保留；本次没有伪造或拼补残缺 JSON，而是从缓存的前置阶段续接小批规划。
