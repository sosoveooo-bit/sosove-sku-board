# 导演多图请求上传超时

## 定位

最新德国任务 46d141fa7c074013893688e0fae6c4e3 在产品分析阶段失败。连续记录约 17–20 秒，terra 与 sol 都出现 write timeout / SSLWantWriteError。相同接口 `/models` 验证 TLS 的请求约 1.14 秒返回 HTTP 200。12 张原图合计约 25.22 MB，分析用 JPEG/Base64 已压缩到约 3.55 MB。

本机 requests 2.33.1 / urllib3 2.7.0 在开始接收响应前，上传仍使用连接 socket 的超时。旧代码 `(connect=8, read=120)` 使多图上传也只获得 8 秒，轮换模型重复上传同一请求。

## 修改

- 增加仅供导演请求使用的 requests adapter：TCP/TLS 连接保持短时限；上传独立默认 90 秒（`AI_DIRECTOR_WRITE_TIMEOUT` 可设 5–180 秒）；等待回复使用原设置并扣除已使用的请求时限。
- JSON 按 64 KB socket 写入，保留原 Content-Length 和完整请求字节；分段不是额外 HTTP 请求，不改变图片分辨率。
- 独立 adapter/pool/connection 类，不全局修改 requests/urllib3，也不修改图片生成节点。兼容原代理配置并继续 TLS 证书校验；无新增依赖、无库级 POST 重试。
- 上传、TLS、连接等接口级错误停止同一节点的模型名轮换，明确显示接口传输错误。已有策划和产品缓存保留。
- 验证脚本每轮最多调用一次实际产品分析并保存成功结果，拦住下游策划调用，不提交整套图片生成；若产品身份存在冲突，保留该结果交由用户确认。首次验证上传问题消失，但等待回复超时；随后纠正上传挤占原有读取窗口的预算处理，再进行一轮验证。
- 记录不含正文的上传完成状态、上传耗时、整次耗时，便于区分以后发生在上传阶段还是等待回复阶段的问题。

## 验证项目

测试连接/上传/读取时限隔离、整体剩余时限、取消、写入异常、代理池隔离、TLS 默认校验、无隐藏重试、请求字节与 Content-Length 不变。回归既有 JSON 模式、模型链、产品缓存与续跑逻辑。

## 实际结果

- 79 项 Visual Agent 测试、9 项新上传传输测试、3 项模型链测试和 3 项 multipart 测试通过，共 94 项不同测试。
- 简短真实模型请求约 6.4 秒返回有效 JSON，TLS 校验保持开启。
- 第二轮 12 图产品分析实测：上传 11.110 秒，HTTP 请求总耗时 92.337 秒，成功收到并解析产品分析。上传超过原 8 秒连接限制，验证了修复的实际作用。
- 分析结果已写入原计划对应产品缓存，没有创建新的整套计划编号，也没有调用下游生图。产品分析现在返回“需确认实际发货形态、颜色标注”等资料冲突；已向用户询问，未擅自改成已确认。
- 验证记录：工作区 `.run/director-upload-verification-20260918.json`。过程有一次大图响应超时、一次简短探测、一次成功大图分析；未重复生成图片。
