# COD 画面丰富度与旧方案升级

## 现场依据

只读检查最近的德国 24 页已完成策划：24 页均缺少新商业字段；首屏仍指定白底居中，后续包含静态产品、单细节放大等旧安排。新版规则不会改写已保存 Prompt，而面板此前没有明确标识这种差异。

## 本次设计

1. 在原有导演、规划、动态 Prompt 阶段增强画面执行指导：主视觉、实际动作/场景或细节支撑、位置与阅读层次。使用既有字段，保持简短输出。无固定页序、拼图数量、配色或模特配额；用户明确白底、极简、无文字时优先遵守。
2. 最终图片请求直接携带该页 scene、composition、benefitVisualization、informationHierarchy，避免动态作者压缩成“产品 + 标题”。内容来自该页方案，不是通用母版。内部说明与可见文案分开。
3. 创意版本升级至 v5，写入计划及每页数据。旧计划没有版本时保持旧状态，不在同步时伪装成新版。
4. 面板明确显示旧方案提醒与“另存丰富版方案”按钮。点击仅创建准备任务，复制产品资料和引用；默认先策划再确认生图。原任务图片、Prompt、远端运行编号和补图流程保持原样。进行中的任务暂不另存。

## 成本与兼容

没有新增模型阶段、生成后 AI 审核或自动付费重画。丰富度不新增硬性校验错误。新版本使创意缓存重新策划，匹配的产品分析缓存继续复用；先前旧产品分析版本的一次性升级不在此变化范围内。接口及旧版已保存方案继续可提交，升级是显式选择。

## 验证

离线 Python 检查逐页画面安排进入最终 Prompt、版本与缓存分离、旧计划保持可提交、极简例外、各品类通用与前后端版本一致。JS 检查旧方案识别、显式另存、原图/补图保留、预览优先与无网络调用。真实视觉效果仍需新版样张确认；代码测试不代表已经达到公司成片水准。

执行结果：79 项 Visual Agent Python 测试、6 项 multipart/director 兼容测试、6 组 JS 回归与 JS 语法检查通过。确认活跃策划租约和生图任务均为 0 后重载 8793；健康检查正常，线上静态脚本包含 v5 与升级按钮。本次没有提交付费策划或生图调用，没有修改历史计划与产品缓存数据。
